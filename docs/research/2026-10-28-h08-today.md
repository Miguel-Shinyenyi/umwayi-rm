# 2026-10-28: H-08 Today design

Date: 2026-10-28. Source: written record of H-08 design decisions (no prior response existed to quote). Purpose: research data for measurable outcomes. Status: notes, not results.

## Decisions

1. Today is a pure assembly over store reads. buildToday takes asOf and periods explicitly. No clock reads inside, so every run is reproducible and fixtures pin exact sequences.
2. Final order is category rank (overdue, finding, question), then due date plus display name, finding kind, question creation time. Display name beats member id in ordering so fixtures can assert sequences without knowing random ids.
3. Monthly commitments evaluate per period. One-date commitments emit at most one overdue item with all-time paid for that kind. The due date itself is not overdue; the day after is.
4. Reconciliation sorts paper rows before matching, so caller row order cannot change the result. Exact amount wins over amount differs. Each entry matches at most once.
5. Findings and proposal listing joined the store interface with both implementations and conformance cover. HTTP routes still wait for H-09 and H-10.
6. Fixtures are JSON data plus one runner. Each asserts exact sequences, double-run equality, and reverse-seed set equality. Twelve cover clear, overdue, partial, order, loan, questions, findings, mixed, exclusion, alias, and boundary.

## How this is tested

H-08 acceptance is the 12 fixtures green plus the order guarantees. Memory runs locally. The pg conformance extension runs in CI.
