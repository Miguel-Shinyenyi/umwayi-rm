# 2026-10-28: H-09 agent design

Date: 2026-10-28. Source: written record of H-09 design decisions (no prior response existed to quote). Purpose: research data for measurable outcomes. Status: notes, not results.

## Decisions

1. One MCP server, two transports. Stdio serves the inspector with group context from the environment. In-memory transport serves runs and tests over the real protocol with no sockets.
2. Checks live in the tool handlers, never in the prompt alone. Quote containment, the 3-quote cap, member resolution with collision refusal, and the 3-refusal budget all run as code. Refusal feedback names the failing check, never the expected label.
3. Bare first names resolve to every matching member so collisions surface as refusals. Full names and aliases match exactly first in effect, since only one member carries them.
4. The loop ends on the first successful proposal, with turn budget 8 and tool budget 12. Tool results ride as tool messages. Traces record turns, calls, results, and the outcome.
5. The pack is two files: a four-part playbook plus a rules table with cause, scope, and motivating scenarios. Pack v0 ran unchanged because no systematic rule failure appeared.
6. The harness injects today's date into the system prompt after the model dated October to 2025 without it. Production loop paths need the same injection.
7. Empty completions are the observed failure mode: no content and no tool call, moving between runs. No retry exists yet. One lands with H-12 preparation, with tests, not as a silent re-call.

## How this is tested

Handler unit tests, a protocol round-trip test, offline loop tests with a scripted stub, and the annotated live dev runs. H1 counted runs reuse the harness on the frozen test split.
