# 2026-10-29: H-19 edit and answer

Date: 2026-10-29. Source: written record of H-19 design decisions (no prior response existed to quote). Purpose: research data for measurable outcomes. Status: notes, not results.

## Decisions

1. Edits replace the whole payload rather than patching fields, so the stored payload always passes the same validator approval uses. Memory shares one validator between edit and approve; pg mirrors the same rules inline.
2. The audit list lives on the proposal as previous payloads with timestamps, not as a separate table. One treasurer, short lists, and the inbox reads the proposal already made a table disproportionate.
3. Editing clears the verification trail. A trail that judged different numbers would lie, and re-running the claim check on edit would spend a model call the treasurer did not ask for. The next approval rebuilds it.
4. Answers run the agent fresh over note plus answer instead of resuming a loop, because runs are synchronous and short. The question keeps its original run link; new proposals link the new run; the answer text lands in the question's trail.
5. The answered status is a fourth terminal state, not a flag, so the pending inbox naturally excludes answered questions. The contract's expired status was dead text with no implementation and was removed rather than built.

## How this is tested

Conformance cases for edit audit, trail clearing, approve-after-edit, all rejections, and the answered transition on both backends; route tests for edit, answer with run linkage, and failure paths; static console markers for the editor, answer box, and audit display. CI runs typecheck, the full suite including pg, build, and the compose health proof.
