# 2026-10-29: H-18 verification hardening

Date: 2026-10-29. Source: written record of H-18 implementation decisions (no prior response existed to quote). Purpose: research data for measurable outcomes. Status: notes, not results.

## Decisions

1. Approval-time checks live in the stores so both backends enforce them identically: schema revalidation, member-still-unique (blocking on conflict), and quote attachment (recorded, non-blocking, because page proposals carry no quotes). The trail merges with any earlier entries instead of overwriting.
2. The claim check runs in the approve route before the store call, only when a model is configured. It fails closed on inconclusive output, records the failed verdict on the pending proposal, and refuses with the reason. Model-off approvals record code-checks-only by omission.
3. Runs persist with the intake text as the reference, so coverage is computed at read time from current proposal quotes rather than stored. Proposals link their run id; the console renders trails and fetches traces per proposal.
4. The reminder check compares normalized text against every other member's display name, first name, and aliases. Target names stay allowed. This is the one money-rule-adjacent check that code can do exactly; judging tone stays in the pack.
5. The member resolver moved to the ledger layer with a re-export from the tools module, so stores, tools, and routes share one implementation.

## What the workshop run taught

The session 1 memo passed every deterministic rule and still failed 5 claim findings. That single observation justified G2: rules catch shape, a second model pass catches overreach. The branched run then showed the loop working: two refusals, a revision, a filed memo. Umwayi-rm now has the same shape at approve time.

## Limits

The claim check adds one model call and its latency to every approval when keys are set. Coverage counts quote overlap per line, which misses paraphrase. No browser pass of the new console views.

## How this is tested

Conformance cases for proposals reads, trails, and runs on both backends; stubbed claim verdicts for pass, fail, and skip; route tests for run detail, coverage, intake linkage, and the reminder refusal; static console markers. CI runs typecheck, the full suite including pg, build, and the compose health proof.
