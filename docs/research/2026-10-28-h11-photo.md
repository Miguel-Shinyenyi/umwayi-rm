# 2026-10-28: H-11 photo reading and reconciliation

Date: 2026-10-28. Source: written record of H-11 design decisions (no prior response existed to quote). Purpose: research data for measurable outcomes. Status: notes, not results.

## Decisions

1. Photo reading runs outside the agent loop. The loop passes text-only messages, and the design already splits the work this way: the model reads a page into rows, code matches rows to entries. No compare_page MCP tool was added; the route calls comparePaper directly.
2. The row parser is strict. Member name, positive integer amount, and YYYY-MM period are all required, and a missing JSON array throws. Misreads fail loudly through the route error path, never as silent wrong rows.
3. The H-08 matcher stays untouched. Its strict display-name-or-alias contract is frozen by passing tests. The page route resolves member text first with the first-name-tolerant resolver, then compares canonical display names. Unknown or colliding names become question proposals plus only-on-paper findings, never guesses.
4. Matched rows create nothing. Only mismatches become entry proposals, and every mismatch kind becomes a finding: only on paper, amount differs, only in ledger. Page proposals set occurredOn to the first of the row period and sourceRef to page.
5. Model-off photo intake answers 503 with code model_off. Photo has no manual fallback inside the route; the treasurer uses typed intake or manual entry instead.

## Limitations

- The live read check used a clean printed page, not handwriting. The model read all 3 rows exactly, but handwriting reading quality is still untested. The demo should use printed-style pages or state the limit.
- The first probe clipped long lines off a too-narrow canvas and the model read a clipped 500 as 5. Synthetic image checks must verify the canvas fits the text before judging the model.

## How this is tested

Parser unit tests, a stubbed-fetch reader test asserting the image_url wire shape, and route tests over the memory store covering match, mismatch, unknown name, auth, and the findings list. CI runs typecheck, the full suite including pg, build, and the compose health proof.
