# 2026-10-29: H-15 H2 archive run

Date: 2026-10-29. Source: written record of H-15 design decisions and results (no prior response existed to quote). Purpose: research data for measurable outcomes. Status: results, one seed.

## Decisions

1. The corpus is 28 files: 12 meeting notes, 12 ledger months with chained balances, the current constitution, and 3 dated amendments. Every archive-backed expected answer was verified present before any run. Identity answers live in the core only.
2. Archive storage matches the contract: verbatim text, SHA-256 at save time, one-line gist, gist-only listing. Recall returns verbatim plus checksum and refuses unknown pointers gracefully so the agent can try another.
3. Conditions share one core and one scorer. T keeps the constitution plus the 4 most recent dated items. R retrieves 4 items by deterministic word overlap, no embeddings. A sees the 28-gist index and recalls through the loop. F loads all 28 verbatim as the reference.
4. The scorer strips parentheticals, normalizes number words, stems plurals, and maps negation to no. Three scorer bugs were found and fixed with unit tests (plurals on dev, comma numbers and negation on test). Raw run files stay untouched; the rescore of frozen answers lives in docs/evals/h2-seed7-analysis.json with the flipped ids listed.
5. The model answers in content after recalling instead of calling answer_question, so content answers count with the mechanism flagged per question. The metric is answer correctness; tool discipline is recorded, not scored.

## Reading

H2 is not supported on seed 7. A beats T (19 versus 13) but trails R (19 versus 20), and the rule needs A above both. Plain word-overlap retrieval matches full context at the lowest token cost, while the agentic archive costs six times more and drops one question the core already answered: the model refused an identity question with zero recalls. Truncation fails exactly as designed, honestly reporting missing records instead of guessing.

## Limits

One seed; the protocol names no seed count for H2. The corpus is small enough that top-4 overlap nearly always contains the answer, which flatters R. A larger or noisier corpus would be needed to separate gist-plus-recall from plain retrieval.
