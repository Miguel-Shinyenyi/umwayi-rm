# 2026-10-28: H-05 eval data design

Date: 2026-10-28. Source: written record of H-05 design decisions (no prior response existed to quote). Purpose: research data for measurable outcomes. Status: notes, not results.

## Decisions

1. Location evals/ at repo root, split h1/ and h2/. Scenario inputs live apart from docs/evals/ run outputs.
2. One JSON file per set with an embedded split label per item. Freeze is the SHA-256 of each file plus the test id ranges, recorded in docs/experiments.md. Any edit changes the hash.
3. H1 labels are binary and code checkable: propose with an exact expected entry, or ask with a reason. Amount differs proposes the stated amount with a gap flag, never the commitment. Two person notes are ask labeled so scoring stays binary.
4. H1 scenarios share one group fixture: 12 members, a Brian collision pair, monthly commitments, one loan repayment. Member refs resolve against group.json.
5. H2 questions carry needs lists naming the history facts they require. The 12-month history gets built for H-15 to satisfy them, instead of guessing questions from unwritten history.
6. Voice note versus typed note is an input type on each H1 scenario. Transcripts ship now. Audio for a subset follows when H-10 needs spoken input.

## How this is tested

H1 runs score propose versus ask plus entry equality on the frozen test ids. H2 runs score answer labels once the history exists. The hashes guard the freeze.
